## 概述

本次改造涉及 6 个需求点，核心目标是：

1. 将普通订单与现场订单融合到统一的订单列表
2. Tabbar "订单"改为快速进入现场开单创建页
3. 车费从创建时前置收取改为结束服务时确认
4. 创建页面增加起步时长计费规则提示
5. 个人中心入口调整

## 二、统一订单列表页改造（pages/order/index.vue）

### 2.1 状态 Tabs 配置

从 8 个扩展为 10 个平铺 tab：

| 序号 | Tab 名称 | status 值 | 对应订单类型 |
|------|----------|-----------|-------------|
| 1 | 全部 | 0（不传） | 全部 |
| 2 | 待付款(普通) | 10 | 普通订单 |
| 3 | 待接单 | 20 | 普通订单 |
| 4 | 已接单 | 30 | 普通订单 |
| 5 | 待开始 | 15 | 现场订单 |
| 6 | 进行中 | 40 | 普通+现场 |
| 7 | 待付款(现场) | 45 | 现场订单 |
| 8 | 待评价 | 50 | 普通+现场 |
| 9 | 已完成 | 60 | 普通+现场 |
| 10 | 已取消 | 70 | 普通+现场 |

每个 tab 调用 `getOrderPage({ status })` 传入单个状态码，接口返回混合类型的订单列表。

### 2.2 订单卡片新增类型标签

在订单卡片上新增"订单类型"标签：
- `type === 1` → "普通订单"（蓝色标签）
- `type === 2` → "现场订单"（橙色标签）
- 位置：订单号旁边或卡片头部

### 2.3 点击跳转逻辑

点击订单卡片时判断 `type` 字段：
- `type === 1` → `navigateTo('/subpkg/order/detail?orderId=xxx&status=xxx')`（普通订单详情）
- `type === 2` → `navigateTo('/subpkg/onsite/detail?id=xxx')`（现场订单详情）

### 2.4 API 兼容

继续使用现有 `getOrderPage` 接口，列表项新增 `type` 字段（1=普通，2=现场），前端按类型渲染和跳转。

## 三、现场开单创建页改造（pages/onsite/create.vue）

- 从 `subpkg/onsite/create.vue` 迁移至 `pages/onsite/create.vue`
- 作为 tabbar "订单"页面，进入即显示创建表单
- 页面标题保持"创建订单"

### 3.2 移除车费输入

- 删除 `returnTravelYuan` 相关状态变量
- 删除车费输入框 UI 及校验逻辑
- 创建请求体删除 `returnTravelAmount` 字段
- 创建请求仅包含：`requestId`、`serviceType`、`customerType`、`memberUserId`（会员时）

### 3.3 新增计费规则提示

在创建按钮上方增加提示说明区域（灰色背景文字提示块），随服务类型动态变化：

| 服务类型 | 起步时长 | 提示文案 |
|---------|---------|---------|
| 台球指导 | 1 小时 | 温馨提示：台球指导起步时长为1小时，不足1小时按1小时计费，超出部分按分钟（单价/60）计费。 |
| 潮玩领航 | 2 小时 | 温馨提示：潮玩领航起步时长为2小时，不足2小时按2小时计费，超出部分按分钟（单价/60）计费。 |
| 酒艺品鉴 | 4 小时 | 温馨提示：酒艺品鉴起步时长为4小时，不足4小时按4小时计费，超出部分按分钟（单价/60）计费。 |
| 影视赏析 | 8 小时 | 温馨提示：影视赏析起步时长为8小时，不足8小时按8小时计费，超出部分按分钟（单价/60）计费。 |

起步时长映射在前端硬编码（业务规则固定，不由后端返回）。

### 3.4 服务类型配置来源

服务类型列表仍从 `getCoachProfile()` 返回的 `serviceItems` 中获取，包含各服务的小时单价。

## 四、车费后移至结束服务（现场订单详情页改造）

### 4.1 删除"修改返程车费"入口

- 删除待开始状态下的"修改返程车费"按钮
- 删除弹出层组件 `showReturnTravelPopup`、`editTravelYuan`、`travelUpdating` 等状态
- 删除 `updateReturnTravel` API 调用
- 待开始状态下返程车费显示为 0 元，标注"待结束时确认"

### 4.2 结束服务时车费输入（底部弹出层）

**触发：** 点击"结束服务"按钮 → 弹出底部车费输入面板 → 确认后调用结束接口

**底部弹出层内容：**
- 标题："确认返程车费"
- 说明："请输入实际返程车费（0～50元）"
- 数字输入框（默认 0，支持小数点后两位）
- 取消按钮 / 确认结束按钮（主按钮）

**校验规则：**
- 不能为空
- 不能为负数
- 最大值 50 元（5000 分）
- 0 是有效值，不能当作未填写
- 提交时转换为整数分（乘以 100，四舍五入取整）

### 4.3 API 调整

`finishOnsiteService` 请求参数调整：
```js
// 之前
{ orderId }

// 之后
{ orderId, returnTravelAmount }  // 单位：分，范围 0～5000
```

### 4.4 网络重试与幂等处理

- 结束请求超时/失败时，**先查询订单详情**确认当前状态
- 若订单已处于待付款（45）/ 已完成（60）等终态，说明首次请求已成功
- 直接展示服务端返回的车费和金额，**禁止用本次重试输入的车费覆盖服务端返回值**
- 始终以接口返回的 `returnTravelAmount`、`serviceAmount`、`payAmount`、`originalAmount`、`totalAmount` 为准

### 4.5 异常结束

管理员异常结束接口不接收车费，助教端无需改动。展示异常结束订单时以接口返回的 `returnTravelAmount` 为准（服务端固定为 0）。

## 六、注意事项

1. **不操作 git** — 所有改动完成后由用户检查，确认后再提交
2. **向后兼容** — `getOrderPage` 返回的列表项新增 `type` 字段，不影响已有字段
3. **车费单位** — 接口传输单位为分，前端展示单位为元，注意转换
4. **幂等安全** — 结束服务的重试逻辑必须以服务端返回值为准，禁止客户端覆盖
5. **Tabbar 限制** — `pages/onsite/create.vue` 作为 tabbar 页面，不能使用 `navigateTo` 跳转，需使用 `switchTab`
